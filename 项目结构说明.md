# 账目配平工具项目结构说明 / Project Structure Overview

## 中文

### 当前版本定位

当前版本是一个本地离线可运行的 `entry-centered` 账目配平工具。
核心思路是不再以“项目归组”为中心，而是以每条分录的 `remaining_amount` 为唯一核心状态。

### 目录结构

- `main.py`
  - 程序入口
- `src/ledger/ui/`
  - `main_window.py`：主窗口与左侧导航
  - `import_page.py`：导入账目文件并触发自动匹配
  - `results_page.py`：分录级结果页，包含未配平分录、候选建议、已匹配记录
  - `settings_page.py`：AI 接口设置
- `src/ledger/storage/`
  - `db.py`：SQLite 连接与表结构初始化
  - `repository.py`：entries / match_records / match_links 的读写与重算
- `src/ledger/services/`
  - `importer.py`：读取 Excel/CSV，识别 `row_type`、`amount_side`、初始化金额状态
  - `matching_engine.py`：自动匹配主逻辑
  - `ai_suggester.py`：AI 语义辅助，仅分析金额已成立候选
  - `exporter.py`：导出 Excel 结果
  - `attribution.py`：保留为轻量文本辅助模块
  - `balance_trace.py`：兼容性保留的轻量追踪封装
- `tests/`
  - `test_repository_entry_centered.py`
  - `test_importer_entry_centered.py`
  - `test_matching_engine.py`
  - `test_ai_suggester_entry_centered.py`
  - `fixtures/sample_ledger.csv`
- `scripts/`
  - `build-windows.ps1`：Windows 打包脚本

### 关键数据模型

- `entries`
  - 保存导入后的原始分录和状态字段
  - 核心字段：`row_type`、`amount_side`、`original_amount`、`remaining_amount`
- `match_records`
  - 记录每一次匹配动作
- `match_links`
  - 记录每条匹配动作具体使用了哪些 entry、各自用了多少金额

### 当前主流程

1. 用户导入明细分类账
2. `importer` 规范化数据并初始化 `remaining_amount`
3. `matching_engine` 自动执行：
   - `1:1` 完全匹配
   - `1:1` 部分匹配
   - `1:N / N:1` 组合匹配
4. `results_page` 展示：
   - 未配平分录
   - AI/自动候选建议
   - 已匹配记录
5. 用户可手工确认匹配或取消已有匹配
6. 用户可导出 Excel 结果

### 当前 UI 结构

第二版本当前只保留 3 个主导航入口：

- 导入
- 结果
- 设置

旧版“规则”页已从界面中移除，以保持版本简洁。

## English

### Current Version

The current version is a local offline `entry-centered` reconciliation tool.
It no longer relies on project grouping as the primary business model. Instead, each entry is driven by `remaining_amount` as the single core state field.

### Directory Layout

- `main.py`
  - application entry point
- `src/ledger/ui/`
  - `main_window.py`: main window and left navigation
  - `import_page.py`: imports ledger files and triggers auto-matching
  - `results_page.py`: entry-level result view with unmatched entries, candidate suggestions, and confirmed matches
  - `settings_page.py`: AI configuration
- `src/ledger/storage/`
  - `db.py`: SQLite connection and schema initialization
  - `repository.py`: read/write and recalculation logic for `entries / match_records / match_links`
- `src/ledger/services/`
  - `importer.py`: reads Excel/CSV, detects `row_type`, infers `amount_side`, initializes amount state
  - `matching_engine.py`: core automatic matching logic
  - `ai_suggester.py`: AI semantic assistant for amount-valid candidates only
  - `exporter.py`: Excel export
  - `attribution.py`: retained as a lightweight text helper
  - `balance_trace.py`: lightweight compatibility wrapper
- `tests/`
  - repository, importer, matching engine, and AI validation tests
  - `fixtures/sample_ledger.csv`
- `scripts/`
  - `build-windows.ps1`: Windows packaging script

### Core Data Model

- `entries`
  - stores imported ledger rows and runtime state
  - key fields: `row_type`, `amount_side`, `original_amount`, `remaining_amount`
- `match_records`
  - stores each reconciliation action
- `match_links`
  - stores which entries participated in each match and how much amount was used

### Main Workflow

1. User imports a detailed ledger file
2. `importer` normalizes data and initializes `remaining_amount`
3. `matching_engine` runs:
   - `1:1` full match
   - `1:1` partial match
   - `1:N / N:1` combination match
4. `results_page` shows:
   - unmatched entries
   - auto/AI candidate suggestions
   - confirmed match records
5. User can confirm matches manually or cancel existing matches
6. User can export the result to Excel

### Current UI Navigation

Version 2 now keeps only three primary navigation entries:

- Import
- Results
- Settings

The old Rules page has been removed from the interface to keep the product clean and focused.
